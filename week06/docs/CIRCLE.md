## 场景定义

人和车交替、等角度排列在圆周上，同时朝圆心方向出发，并以各自初始位置的对径点为终点。默认4人4车、初始半径12 m，观察120 s。初始圆周只是排布参考线，不是实体边界，也没有圆环道路。相邻类别交替不意味着同直径两端必定异类：4对主体时，同直径两端是同类。

主体中心进入终点0.35 m范围并停稳才计为到达。已经到达的主体保持原位置并继续作为实体障碍；没有到一个就删除一个，也没有把位置吸附到终点。终点停车同样受纵横向减速度约束。

## 现有算法如何用于多方向运动

原控制器只认识沿路纵向和横向。本次没有为人车分别设计控制器，而是在每个主体的固定初始朝向上建立局部坐标，再复用原来的期望运动、选边、速度限制和互惠制动公式。

```text
初始位置 p_i(0) = R (cos θ_i, sin θ_i)
目标位置 g_i = −p_i(0)
纵向单位向量 e_i = (−cos θ_i, −sin θ_i)
横向单位向量 n_i = (−e_iy, e_ix)
p_i(k+1) = p_i(k) + Δt [u_i(k+1)e_i + w_i(k+1)n_i]
```

计算主体i的控制时，将所有位置、速度投影到(e_i,n_i)。其他主体的旋转矩形投影为该坐标系中的包围矩形：投影长度/宽度由两轴上的支撑半径计算。其他主体朝向在e_i方向的分量大于1e−8时归为同向，其余归为相向；这是对原二方向规则的明确适配，不能称为已有完整多方向规划能力。

默认全体在各自局部坐标取同一侧(+n_i)，避免给不同全局朝向硬指定同一个世界坐标侧。交互目标侧移量为2.5 m；代码用宽度 `2×2.5 + 主体宽度 + 2×墙边裕度` 的虚拟路径带复用原横向目标和慢行公式。这里没有实体墙，SFM墙力关闭。无交互时恢复各自直径路径。

车辆横向速度默认0 m/s，另用0.2 m/s作对照；行人0.7 m/s。车速基值3 m/s，人速1.3 m/s；加速度、制动能力、松弛时间、0.2 m侧向间距和0.6 m纵向间距沿用原参数。随机性仍仅为速度±8%扰动，每配置种子0–4，三模型配对使用相同初态。

本次必要改动是坐标适配、对径终点停车和不同朝向的碰撞几何。主体初始朝向固定，侧移不引起车身转向，尚无转向角或自行车模型。投影包围矩形对斜向邻居较保守，可能增加停车；因此僵持既反映局部策略限制，也可能受到这项近似影响。

## 碰撞、完成与停滞

- 所有主体同步计算控制、同步推进，步长0.05 s。
- 物理检测使用固定朝向矩形的分离轴定理（SAT），计算整个步内的接触时刻，避免只查帧端漏掉交叉穿越。
- `min_pair_gap_m`在此场景为全步SAT间距的保守下界，不是原直路的精确欧氏间距。下界不足只能说没有证实裕度足够，不能据此声称发生接触；碰撞由独立连续SAT检测确定。
- 全体到达且停稳为completed；检测到实体接触为collision；所有未到达主体二维速度低于0.025 m/s持续8 s为deadlock_policy；120 s未结束为timeout。
- 本场景不使用窄路的2.4/2.8 m断面阈值，也不使用圈数、检测线通量或周期接缝指标。

## 结果与原因边界

1. 单人单车中，统一规则和修正版均5/5完成，说明向心坐标、终点和回归路径能形成完整穿越；纯SFM在该组均僵持。
2. 默认4人4车中，三模型均5/5僵持，未发生碰撞；车辆允许0.2 m/s侧移后仍未全部通过。未通过不能写成“理论上没有空间”。
3. 2人2车中，纯SFM均发生碰撞；规则和修正版均等待。其余已测多主体设置也未全部到达。
4. 当前主体依据局部投影和独立停止空间限制行动，没有全局预约、倒退或交叉口交替放行。多个径向路径可能互相约束；不同朝向包围矩形投影又会放大占用。因此这是现有规则迁移后的失败结果，不是已证明真实场景必然无解。

没有为了获得成功曲线取消碰撞或把主体挪开，也没有把新增协调算法混入本次基线。后续若加入通行顺序或二维路径规划，应作为另一组明确标记的修正实验。

## 复现

从项目根目录运行：

```powershell
python -m pvsim run --config configs/ring.json --out results/custom_circle
python -m pvsim circle --seeds 5 --out results/circle_crossing
```

原沿环周期运动的150次对照及2个失败案例已从结果集合中删除。当前总计668次：360次原规则扫描、120次直路/缩窄三模型对照、48次SFM参数探索、11次失败修正、9次基础演示、120次向心穿越。数量包含演示和重复配置，不表示668个独立样本。
